# 周转箱内衬混箱追溯与召回

从必需适配特征归并规格，并在已签核的混箱调拨后按批号给出召回范围。

澄浦装配包装组为两座工厂的三条装配线维护循环周转箱及可替换内衬。包装工程师从工装台账提取工位必需的箱体接口、支撑位及让位特征，规格管理员据此归并内衬并签核混箱调拨；调拨之后若有原批次需要召回，仓管登记入库与调拨流水，复核员核对版本，采购据交付页面按库位排查。

- 同箱型的内衬可能有不同支撑或让位要求，单看箱体尺寸容易误判共用。
- 混箱调拨只记录起止库位和件数，事后无法凭记录还原某批号落在哪个箱子。
- 补录早先的单据会打乱登记顺序，按录入顺序推算库存会把批次记错库位。

## 业务模块

| 模块 | 用途 |
|---|---|
| 业务总览 | 查阅业务口径、当班流程、最新运行与召回待处理事项。主管可以核对审计记录。 |
| 规格与适配特征 | 下载「澄浦内衬必需适配特征_20261121.csv」并核对字段。分析员可导入 UTF-8 CSV，保留数据指纹和原始行。 |
| 归并参数 | 选择批次和参数并提交后台计算，可从运行列表追踪状态。 |
| 归并与切树 | 查看业务指标、证据表和解释，通过来源链接回查数据。 |
| 打样复核 | 查看待处理或已完成记录。复核主管可提交打样复核及依据。 |
| 规格清单交付 | 按批查找结果，核对复核状态并下载相应的 CSV。 |
| 召回流水登记 | 关联签核记录登记入库（库位、批号、件数），调拨只登记起止库位、件数和发生时间；可补录、可作废。 |
| 召回版本 | 按实物顺序重放每次登记，库存不足的候选版本暂缓发布，上一版照常可查。 |
| 召回交付范围 | 按召回批号给出各库位可能剩余件数的精确上下界，可下载 CSV。 |

## 启动

docker compose up -d --build --wait

## 演示流程

1. 11 月 21 日 08:40，包装工程师将 8 份待归并规格整理到「澄浦内衬必需适配特征_20261121.csv」。
2. 在「规格与适配特征」导入台账，核对 CP-A01 至 CP-C02 的规格编号和必需特征。
3. 在「归并参数」将距离切线设为 0.40 并运行，查看切出的 4 个候选组。
4. 在「归并与切树」追溯 CP-B03 的归并步骤，核对它与 CP-B01 的距离 0.60，以及两侧各自要求的特征。
5. 把切线改为 0.60 重跑，核对 CP-B03 进入 B 组后整批得到 3 个候选组。
6. 在「打样复核」记录 B 组定位孔和传感器让位的实物验证要求，签核后在「规格清单交付」导出。
7. 演示数据自带「调拨单 CP-2611-1118」及三笔入库、三笔调拨。在「召回流水登记」可见最后一笔补录的早先入库按实物时间排在最前。
8. 在「召回交付范围」按 R-2611-01 / R-2611-02 / R-2611-03 查看各库位精确上下界；单批号入库时区间收敛为唯一值。
9. 尝试登记一笔超出库位当时总件数的调拨：版本转为暂缓发布，交付页面仍显示上一版；在「召回流水登记」作废该笔并填写原因后，版本恢复发布。

## 计算口径

### 规格归并

- 每条规格对应一组必需适配特征。用 | 分隔，去除特征首尾空白并按集合去重；特征名称按原有大小写匹配。
- 两条规格的 Jaccard 距离为仅出现在一侧的特征数除以两侧特征并集数，取值为 0 至 1。
- 完全链接用两个组之间最远的规格对定义组间距离。每一步合并距离最小的组对，同距按两个组各自最小的规格编号折叠大小写后排序。
- 切树保留距离小于或等于切线的归并。结果列出每步最远规格对、两侧独有特征，以及超线最远的至多 50 个规格组合。
- 候选组供实物打样复核，共有特征及各规格的独有要求应一并核对。

### 召回上下界

- 入库登记关联签核记录、库位、批号和件数；调拨只登记起止库位、件数和先后顺序，不带批号。
- 所有流水按“发生时间 + 登记顺序”重放；补录早先的单据会按实物顺序重排，而不是按录入顺序。
- 调拨不区分批号，因此不能假定混箱先到先出。各库位剩余量在“所有与流水相容的批次分配”上取上下界：以时间层展开、库位容量为实物总件数的单商品流求最大流，上界为可流向该库位末层的最大件数，下界为入库总件数减去可流向其余库位的最大件数。流精确覆盖全部相容分配，返回的是可达区间，而不是某一套先到先出的推算值。
- 任何一步调拨超过该库位当时实物总件数时，候选版本暂缓发布并记录首个不足步骤；已发布版本保持可查，直到修正或作废后重算。
- 同一笔登记以请求键去重：重试返回原记录且不重复扣库；请求键相同但字段不同返回 409。作废记录保留审计痕迹但不参与重算。
- 已发布版本按自身存档的流水计算并缓存上下界，后续补录或库存不足不影响历史版本的交付结果。

## 本地开发

| 组件 | 实现 |
|---|---|
| 前端 | Nginx 与原生 HTML、CSS、JavaScript。`frontend/src/pages` 放页面，`components/common` 放共用表格、图表及表单。 |
| API | Python 3.11、FastAPI、SQLAlchemy。`backend/src/domain` 放本项目字段、业务计算和演示数据，`routes` 放接口，`models` 放表模型。召回上下界见 `domain/recall.py`，登记与版本发布见 `services/recall.py`。 |
| 后台 | 独立 Python worker，通过 Redis 唤醒，从数据库租约领取计算，CSV 写入共享卷。 |
| 数据 | MySQL 8 存储批次、运行、审计与召回流水。`backend/scripts/seed_demo.py` 和应用启动时的演示种子都可安全重复执行。 |

改动前端后执行 `docker compose up -d --build frontend`。改动接口或算法后执行 `docker compose up -d --build backend worker`，再刷新浏览器。如需保留数据，停止时执行 `docker compose down`。使用 `docker compose down -v --remove-orphans` 会清除该项目的数据库、Redis 和报表卷。

`.env.example` 中的 `COMPOSE_PROJECT_NAME`、`FRONTEND_PORT`、`BACKEND_PORT`、`DB_PORT`、`APP_SUBNET` 控制项目隔离。`DB_PASSWORD`、`JWT_SECRET` 和 `SEED_DEMO` 为本机演示默认设置。后端 `constants/enums.py` 与前端 `src/constants/enums.js` 保持角色、运行状态和复核状态一致。项目许可证见 `LICENSE`。
